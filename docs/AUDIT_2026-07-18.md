## 2. Hallazgos (evidencia)

### F1 — CRÍTICO: scoring mandarín crashea
`backend/scoring.py`, en `_score_cjk`, penúltimas líneas:
```python
grade = EchoScorer._calculate_grade(None, overall_sim)
```
`_calculate_grade` es `@staticmethod` con firma `(accuracy)`. Recibe 2 args → `TypeError`
→ `/api/score` y `/api/practice/analyze` devuelven 500 para `language="zh"`.

### F2 — CRÍTICO: Whisper fuerza inglés
`backend/whisper_service.py` → `transcribe()` pasa `language="en"` hardcoded.
`main.py` `/api/practice/analyze` llama `whisper_service.transcribe(wav_path)` sin idioma,
aunque recibe `language` del form. Español/mandarín se decodifican como inglés → scores basura.
Existe `transcribe_with_language()` que acepta idioma y **nadie llama** (dead code útil).

### F3 — ALTO: cache TTS con `hash()` no determinista
`backend/main.py` (en `/api/tts` y en `/api/practice/analyze`):
```python
text_hash = str(abs(hash(request.text)))
```
- `PYTHONHASHSEED` aleatorio por proceso → el mismo texto genera OTRO filename en cada
  restart → cache inútil + `audio_cache/` crece sin límite.
- El key no incluye idioma ni proveedor → mismo texto en `en` y `es` colisiona al mismo
  archivo → se sirve audio del idioma equivocado.

### F4 — ALTO: CD backend roto y enmascarado
`.github/workflows/echo-cd.yml`, job `deploy-backend`:
- Step "Build and push image" define `IMAGE=...` como variable de shell; el step
  "Deploy to Cloud Run" (otro proceso) usa `"$IMAGE"` → vacío → `gcloud run deploy --image ""` falla.
- `continue-on-error: true` en `backend-test`, `backend-build` y `deploy-backend`
  esconde TODOS los fallos: CI verde mintiendo.
- `deploy-backend` NO monta el secret `ELEVENLABS_API_KEY` (cloudbuild.yaml y deploy.sh sí)
  → un deploy por Actions dejaría TTS solo-Kokoro sin avisar.
- 3 rutas de deploy divergentes (workflow / cloudbuild.yaml / deploy.sh) con memoria
  distinta (8Gi/4 vs 4Gi/2) y env distinto.

### F5 — MEDIO: sin límite de upload ni rate limit
`/api/practice/analyze` y `/api/transcribe` hacen `await audio.read()` a memoria sin cap.
Endpoint público (`--allow-unauthenticated`) que quema CPU (whisper) y dinero (ElevenLabs).

### F6 — MEDIO: docker-compose roto
`docker-compose.yml`: mapea `8000:8000` pero el Dockerfile arranca uvicorn en `${PORT:-8080}`.
Volumen `echo_db_data:/app/data` pero la DB se escribe en `/app/echo.db`
(`database.py`: `DATABASE_PATH = Path("echo.db")`) → sin persistencia real.
`backend/.env.example` documenta `DATABASE_URL` que el código **nunca lee**.

### F7 — MEDIO (aceptado para demo): SQLite efímero en Cloud Run
`min-instances=0` → cada scale-to-zero borra sesiones/progreso. Para demo OK.
Largo plazo: volumen GCS/Cloud SQL/Turso. NO arreglar ahora; documentar en README.

### F8 — BAJO: frontend/Dockerfile target `production` roto
`npm ci --ignore-scripts --omit=dev` y luego `npm run build` → vite es devDependency → falla.
`vite preview` sin `--host` no es accesible desde fuera del contenedor. (Netlify no lo usa;
o se arregla o se borra el target.)

### F9 — MEDIO: streaks nunca calculados
`database.py`: `streak_days` se inserta con default 0 y jamás se actualiza.
README y UI (ProgressPage) prometen racha. Implementar cálculo o quitar de UI.

### F10 — BAJO: dead code / drift
- `backend/main.py`: import `AnalyzeResponse` sin uso (el endpoint devuelve dict plano).
- `kokoro_service.generate_words()` sin llamadas.
- Tabla `users` (telegram_id) sin uso (resto legacy Telegram) — dejar, no romper schema.
- `.netlify/netlify.toml` tracked pero `.netlify/` está en .gitignore; duplica el
  `netlify.toml` raíz con contenido distinto (sin `npm install`). Netlify usa el raíz.
- `scripts/test_webapp.py` apunta a `echo-pronunciation-23a4fc3a.netlify.app`
  (URL vieja) — el sitio real es `echo-pronunciation.netlify.app`.
- `netlify.toml` raíz usa `npm install`; debería ser `npm ci`.
- `.gitignore` con entradas duplicadas (`__pycache__/`, `.env`, `*.log` dos veces) — cosmético.

### F11 — BAJO: errores filtran internals
Todos los endpoints devuelven `detail=f"...: {str(e)}"`. Aceptable en demo; no bloquea.

### F12 — INFO: CI de tests decorativo
`backend-test` corre mypy con `|| true` y py_compile; no hay NINGÚN test unitario en el repo.
El único "test" es Playwright E2E (`scripts/test_webapp.py`), manual.

### C3 — Cache TTS determinista y por idioma
**Tier:** free/local. **Archivos:** `backend/main.py` (2 sitios: `/api/tts` y analyze).

1. Arriba en main.py añadir `import hashlib`.
2. Reemplazar AMBAS ocurrencias de:
```python
text_hash = str(abs(hash(request.text)))          # en /api/tts
text_hash = str(abs(hash(expected_text)))         # en analyze
```
por un helper único (definir junto a `convert_audio_to_wav`):
```python
def tts_cache_name(text: str, language: str) -> str:
    provider = "el" if ELEVENLABS_AVAILABLE else "kk"
    key = hashlib.sha1(f"{provider}:{language}:{text}".encode()).hexdigest()[:16]
    return f"tts_{key}.wav"
```
y usar `audio_filename = tts_cache_name(request.text, lang)` / `tts_cache_name(expected_text, language)`.
3. Test en `backend/tests/test_tts_cache.py`:
```python
def test_cache_name_stable_and_language_scoped():
    import main
    a = main.tts_cache_name("hola", "es")
    assert a == main.tts_cache_name("hola", "es")
    assert a != main.tts_cache_name("hola", "en")
```
(nota: importar main carga servicios; si tarda por whisper, marcar el test con
`pytest.importorskip` o extraer el helper a `scoring.py`-style módulo `util.py` — decisión
del ejecutor, preferir extraer a `backend/util.py` sin imports pesados.)
**Gates:** pytest OK.
